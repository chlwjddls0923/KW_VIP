# 동작 설명: 텍스트 명령으로 엘리베이터 버튼 누르기

팀원이 발표에서 설명해야 하는 네 가지(관측 데이터, 텍스트가 동작에 주는 영향, 관절 명령으로 바뀌는 과정, 성공률 계산)를 코드 위치와 함께 정리했다.
수치는 모두 이 저장소에서 실행한 결과다(`results/summary.md`, `docs/PROGRESS.md`).

## 1. 전체 흐름

`src/assist/pipeline.py`의 `Assistant.run` ([pipeline.py:59](../src/assist/pipeline.py#L59))이 명령 하나를 처리한다.

1. 관찰 자세에서 시작한다. 팔 관절 [0, 0, −1.6, 0, 0, 0] (`scene.py`의 `Q_OBSERVE`).
2. 텍스트를 해석한다: `nlu.parse` → PRESS(n) / WAIT / REJECT / CLARIFY. PRESS가 아니면 움직이지 않고 메시지를 낸다.
3. head 카메라로 RGB와 깊이를 찍고 버튼을 인식한다: `capture` → `detect`.
4. 층을 확인한다: `nlu.ground`. 명령한 층이 인식된 층 목록에 없으면 움직이지 않고 수행 불가를 알린다.
5. 접근·누름 자세의 IK를 움직이기 전에 미리 푼다. 하나라도 위치 오차가 1 mm를 넘으면 움직이지 않는다.
6. 누른다: 접근 → 법선 방향 직선 누름 → 유지 → 후퇴 → 관찰 자세. 재시도는 없다.
7. 결과 메시지에 목표 버튼의 slide 최댓값(시뮬레이터 버튼 신호)을 적는다. 이 값은 판단에 쓰지 않는다.

## 2. 관측 데이터는 무엇인가

| 관측 | 내용 | 코드 |
|---|---|---|
| 카메라 RGB | 휠체어 머리 위치의 `head_rgb` 카메라, 1280×960 | [camera.py:43](../src/assist/camera.py#L43) `capture` |
| 카메라 깊이 | 같은 카메라의 깊이 영상. 광축 방향 거리(m) | 같은 함수 |
| 카메라 내부·외부 파라미터 | 세로 화각 fovy(72°), 해상도, 카메라 위치·자세(`cam_xpos`, `cam_xmat`) | [camera.py:11](../src/assist/camera.py#L11) `Frame` |
| 숫자 템플릿 | 패널에 쓰인 숫자 그림(장면을 만들 때 그린 PNG)에서 만든 32×32 회색 템플릿 | [perception.py:43](../src/assist/perception.py#L43) `make_template` |

- 인식과 제어의 입력으로 시뮬레이터 정답(버튼 body 위치, 층 이름, slide 값, segmentation 렌더)을 쓰지 않는다. 정답(`Scene.truth()`, [scene.py:220](../src/assist/scene.py#L220))은 채점과 테스트에만 쓴다.
- 인식 순서는 [perception.py:91](../src/assist/perception.py#L91) `detect`에 있다.
  1. 파란 버튼 색(HSV)으로 분할하고, 팽창한 뒤 연결 성분으로 나눈다.
  2. 성분 안의 밝고 채도 낮은 영역을 숫자 라벨로 본다.
  3. 라벨 픽셀을 깊이로 3D 점으로 바꾸고, 모든 라벨 점으로 평면을 맞춰 패널 법선을 구한다(SVD).
  4. 라벨마다 3D 중심과 크기를 구한다.
  5. 라벨을 정면에서 본 모양의 32×32 패치로 펴서 템플릿과 ZNCC로 비교한다. 점수 ≥ 0.5이고 2위와의 차이 ≥ 0.03일 때만 받아들인다.
- 출력은 버튼마다 `{floor, score, margin, center, normal}`이다. 이 중 `center`(라벨 앞면 중심)와 `normal`(패널 법선)이 동작의 목표가 된다.
- 팔은 관절을 측정해 되먹임하지 않는다. 목표 궤적은 기구학으로만 만들고 위치 제어 액추에이터의 ctrl로 보낸다(5절).

## 3. 텍스트는 동작에 어떻게 영향을 주는가

`src/assist/nlu.py`의 규칙 기반 해석기다. 직접 학습한 모델은 없다. 형태소 분리에만 kiwipiepy의 사전 학습 모델을 쓴다.

1. **형태소 분리**: `Kiwi().tokenize(text)`로 토큰의 형태(form)와 품사(tag)를 얻는다 ([nlu.py:242](../src/assist/nlu.py#L242)). 분석기는 한 번만 만든다. 첫 명령에서 약 0.8초 걸리고(공식 run1 기준 846 ms), 그 뒤로는 문장당 약 0.06~0.2 ms다.
2. **층 읽기**: '층'(또는 F) 바로 앞 토큰을 수로 읽는다 ([nlu.py:143](../src/assist/nlu.py#L143)).
   - 숫자, 한자어 수(삼층, 십이층), 서수(셋째), '번째'가 붙은 고유어 수(세 번째)를 읽는다.
   - '지하'나 B가 앞에 붙으면 음수로 읽는다.
   - '3층 말고 / 아니라 / 대신 / 빼고'처럼 취소 표현이 뒤에 붙은 층은 취소한다 ([nlu.py:186](../src/assist/nlu.py#L186)).
3. **부정 판정**: '누르지 마', '안 눌러', '누르면 안 돼', '누를 필요 없어' 같은 네 가지 형태 ([nlu.py:202](../src/assist/nlu.py#L202)).
4. **사건 만들기**: 누르기·이동·대기 낱말과 그 밖의 동사를 사건으로 만든다 ([nlu.py:265](../src/assist/nlu.py#L265)). 이어서 아래 규칙을 적용한다.
   - 과거형('눌렀어?')은 명령이 아니다 ([nlu.py:293](../src/assist/nlu.py#L293)).
   - 부정을 반영한다 ([nlu.py:297](../src/assist/nlu.py#L297)).
   - 조건형('누르면 어떻게 돼?')은 명령이 아니다 ([nlu.py:302](../src/assist/nlu.py#L302)).
   - 조건이 붙은 명령('도착하면 3층 눌러')은 지금 실행하지 않는다 ([nlu.py:316](../src/assist/nlu.py#L316)).
5. **점수**: 사건마다 PRESS·WAIT·OTHER 점수에 더한다. 한국어는 마지막 서술어가 주절이라 뒤쪽 사건일수록 가중치가 크다(w = 1 + i/(m−1)) ([nlu.py:335](../src/assist/nlu.py#L335)).
6. **판정** ([nlu.py:363](../src/assist/nlu.py#L363)): 점수와 층 후보로 PRESS(n) / WAIT / REJECT / CLARIFY를 정한다.
7. **층 확인** `ground` ([nlu.py:381](../src/assist/nlu.py#L381)): PRESS(n)의 n이 인식된 층 목록에 없으면 REJECT로 바꾼다.

텍스트가 바꾸는 것은 **움직일지 말지와 어느 버튼을 목표로 할지**다. 목표 층 n이 정해지면 인식 결과에서 n층 라벨의 중심과 법선을 골라 동작에 넘긴다([pipeline.py:94](../src/assist/pipeline.py#L94)).
같은 작업의 다른 표현 예: '3층 버튼을 눌러줘', '엘리베이터 3층을 선택해 줘', '3층으로 가자', '삼층 좀 눌러 줄래?'는 모두 PRESS(3)이다.
정해 둔 관절 궤적을 재생하지 않는다. 궤적은 매번 인식한 위치로 IK를 풀어 만든다.

### CLARIFY가 나오는 경우

판정 규칙([nlu.py:363](../src/assist/nlu.py#L363)) 가운데 다음 경우에 '몇 층 버튼을 누를까요?'라고 묻고 움직이지 않는다.

1. 세 점수가 모두 작고(< 0.4) 방향 낱말(위, 아래, 위층, 올라가 등)이 있을 때. 예: '위로 가자', '위층으로 가자', '한 층 올라가줘'('한 층'은 층 개수라 층으로 읽지 않는다).
2. WAIT 점수가 PRESS − 0.3 이상이고 OTHER 이상인데 PRESS가 WAIT보다 클 때. 누르라는 말과 기다리라는 말이 비슷한 무게로 섞인 경우다. dev·holdout 문장 가운데 이 규칙으로 CLARIFY가 나온 문장은 없다.
3. 누르라는 판단인데 층 후보가 정확히 1개가 아닐 때.
   - 층이 없는 경우: '버튼 눌러줘', '눌러'
   - 층이 여러 개인 경우: '3층이나 4층 눌러줘', '3층이랑 4층 눌러줘'
   - 모든 층이 취소된 경우: '3층 빼고 다 눌러'

### 알려진 한계

계획서 부록 D에 적힌 한계다. 고치지 않았고, `tests/test_nlu.py`의 `test_known_limits_reproduce`가 아래 결과를 그대로 확인한다.

| 문장 | 결과 | 이유 |
|---|---|---|
| '3층 눌러도 돼?', '3층 누를까?' | PRESS(3) | 의문문은 과거형과 조건형만 거른다 |
| '3층은 누를 일 없어', '3층 누르는 건 좀 그래' | PRESS(3) | 사전과 부정 규칙에 없는 거절 표현은 거르지 못한다 |
| '3층입니다' | PRESS(3) | 층만 말하는 평서문도 누르기로 본다 |
| '이 층 눌러줘' | PRESS(2) | '이'를 수 2로 읽는다 |
| '문 열고 3층 눌러줘' | PRESS(3) | 범위 밖 동작이 앞에 붙으면 뒤의 누르기만 실행한다 |
| '3층 누르고 문 닫아줘' | REJECT | 순서가 반대면 마지막 서술어(닫다)가 이긴다 |
| '3층이랑 4층 눌러줘' | CLARIFY | 여러 층을 누르라는 명령은 지원하지 않는다 |

평가와 문서 작성 중에 추가로 확인한 점은 다음과 같다(규칙은 고치지 않았다).

- holdout '3층 누를까 말까'는 기대가 CLARIFY인데 결과가 REJECT였다. '말'이 '말다'(그만두다)로 쓰였지만 사전에 없는 동사로 처리되어 OTHER 점수가 더 커졌다. 팔은 움직이지 않는다.
- '기다렸다가 3층 눌러'는 PRESS(3)이고, 기다리지 않고 바로 누른다. '-다가'처럼 순서를 나타내는 표현은 처리하지 않는다.
- 인식은 head 카메라에서 팔 베이스에 가려지는 낮은 버튼(약 0.86 m 아래)을 놓칠 수 있다. 이때는 '보이지 않아 수행할 수 없습니다'라고 하고 움직이지 않는다(추가 시험 SV024, 목표 높이 0.83 m).
- 관찰 자세에서 높이 약 0.84 m 버튼은 팔 베이스(link1)가 파란 고리 아래쪽을 일부 가려 고리가 끊기고, 구멍 채우기가 실패해 라벨 픽셀이 기준(25 px)에 못 미쳐 미검출될 수 있다. SV024(4·5층 미검출, 목표 5층 실패), SV060·SV094(5층 미검출, 목표 층이 아니어서 시행은 성공). link1을 투명하게 하면 모두 검출됐다([results/diag/SV024.md](../results/diag/SV024.md)).

## 4. 출력은 어떤 관절 명령으로 바뀌는가

인식 결과의 라벨 중심 c와 법선 n(패널 바깥 방향)을 [motion.py:86](../src/assist/motion.py#L86) `plan_press`가 받는다.

| 단계 | 목표 | 코드 |
|---|---|---|
| 접근 자세 | ee_site = c + (0.08 + 0.012) n, 도구 축 z = −n (버튼 앞 8 cm. 0.012는 손목 캡슐 앞끝이 ee_site보다 12 mm 앞이기 때문) | `plan_press` |
| 누름 자세 | ee_site = c + (0.012 − 0.025) n (라벨 면보다 25 mm 깊이까지 명령. 실제로는 15 mm 끝까지 눌린다) | `plan_press` |
| IK | 관절 한계를 bounds로 넣은 최소자승. 잔차 = [위치 오차 × 100, 0.05 × (도구 축 − z), 0.002 × (q − 시작 자세)]. 위치를 우선하고 방향은 되는 만큼만 맞춘다(수직으로 맞추면 joint5가 한계에 걸린다) | [ik.py:50](../src/assist/ik.py#L50) `IK.solve` |
| 관찰 → 접근 | 관절 공간 5차 보간 2.0초, 0.2초 대기 | [motion.py:67](../src/assist/motion.py#L67) `move_joint` |
| 접근 → 누름 | 법선 방향 직선, 0.03 m/s. 0.02초마다 직전 해에서 IK를 다시 풀어 다음 목표 관절각을 만든다. 끝에서 0.4초 유지 | [motion.py:75](../src/assist/motion.py#L75) `move_line` |
| 후퇴 → 관찰 | 직선 0.06 m/s로 접근 위치까지, 이어서 관찰 자세로 2.0초 보간 | [motion.py:104](../src/assist/motion.py#L104) `execute_press` |
| 관절 명령 | 0.02초마다 목표 관절각 6개를 `data.ctrl`에 쓰고 시뮬레이션을 10스텝(0.002초 × 10) 진행한다. 액추에이터는 위치 제어라 ctrl = 목표 관절각(rad)이다 | [motion.py:51](../src/assist/motion.py#L51) `tick` |

- 보간과 직선 이동은 측정 관절각이 아니라 직전에 보낸 ctrl 목표에서 시작한다. 측정값으로 계산한 IK 증분을 바로 적분하면 손끝이 진동하거나 발산했기 때문이다(계획서 3절).
- 시행 중에 qpos를 직접 대입하지 않는다. 버튼은 물리 접촉으로 눌린다. 손목 캡슐 `wrist_collider`가 버튼 원기둥에 닿아 slide 관절이 밀린다.

## 5. 성공률은 어떻게 계산했는가

1. **조건 고정**: 공식 20회의 시드와 조건(패널 이동·회전·조명·숫자 배치·목표 층·문장)을 `data/eval_protocol.json`에 적고 커밋한 뒤 실행했다. 조건은 `numpy.random.default_rng(seed)`에서 정해진 순서로 뽑는다([protocol.py:61](../src/assist/protocol.py#L61), [protocol.py:71](../src/assist/protocol.py#L71)).
2. **판정** ([protocol.py:115](../src/assist/protocol.py#L115) `judge`):
   - 누르기 시행은 시뮬레이션 30초 안에 목표 버튼 slide 최댓값 ≥ 10 mm이고, 다른 버튼이 모두 < 10 mm일 때 성공이다. 손끝이 가까이 간 것은 성공이 아니다.
   - 움직이면 안 되는 시행은 팔 관절 최대 변화 < 0.02 rad, 모든 버튼 < 1 mm이고 행동 분류가 기대와 같을 때 성공이다.
   - 움직이지 않는 판단 뒤에도 시뮬레이션을 1초 더 진행해 기록한다. 판단 직후 바로 끝내면 정지 판정이 측정 시간 0으로 이루어지기 때문이다([pipeline.py:53](../src/assist/pipeline.py#L53)).
   - slide와 관절 변화는 시뮬레이션 스텝마다 기록한다(`Assistant._monitor`, [pipeline.py:35](../src/assist/pipeline.py#L35)). 채점 전용이다.
3. **실패 유형**: 위에서부터 먼저 해당하는 것으로 분류한다. 실행 예외 / 명령 해석 / 인식 미검출 / 다른 버튼 누름 / IK 도달 불가 / 접촉 10 mm 미달 / 시간 초과.
4. **기록**: 실패한 시행을 빼지 않고 모든 시행을 `trials.csv`에 한 줄씩 남긴다([pipeline.py:164](../src/assist/pipeline.py#L164) `run_trial`).
5. **집계**: 성공 횟수 / 시행 횟수와 Wilson 95% 구간([protocol.py:144](../src/assist/protocol.py#L144)), 일반화 격차(기본 − 변화, %p)를 계산한다. `scripts/eval.py summary`가 `results/summary.md`를 만든다.
6. **재현 확인**: 같은 조건으로 다시 실행한 `results/rerun/`과 `results/official_run2/`의 success 열이 `official_run1`과 25/25 같았다.

| 결과 (official_run1) | 값 |
|---|---|
| 전체 | 20/20 (95% 구간 83.9~100%) |
| 기본 / 변화 | 10/10 / 10/10, 일반화 격차 0%p |
| 명령 점검 | 5/5 |
| 고정 좌표 기준선 | 6/20 (기본 6/10, 변화 0/10) |
| 추가 200회 (공식 밖) | 199/200, 실패 1건은 인식 미검출(SV024) |
