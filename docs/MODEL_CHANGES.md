# 원본 모델 대비 바꾼 것

원본 `assets/wheelchair_piper_lite.xml`은 수정하지 않았다. `src/assist/scene.py`의 `build_scene`이 원본을 읽어 `build/scene.xml`과 숫자 그림 `build/digit_{n}.png`를 새로 만든다.
아래는 그 차이 전부와, 평가할 때 실행 중에 바꾸는 값이다.

## 1. 장면 파일에서 바꾼 것 (`build/scene.xml`)

| 항목 | 원본 | 바꾼 값 | 이유 |
|---|---|---|---|
| 오프스크린 렌더 크기 | 기본 640×480 | `<visual><global offwidth="1280" offheight="960"/>` | head 카메라를 1280×960으로 찍기 위해. 640×480에서는 숫자 오독이 있었다(계획서 3절) |
| 손목 캡슐 충돌 | link6 캡슐은 시각용(`armvisual`, contype 0)이고, 충돌하는 팔 geom은 finger_pad 2개뿐 | `wrist_collider`: 같은 캡슐(fromto 0 0 0 → 0 0 0.13503, 반지름 0.027)에 contype 1, conaffinity 1, group 2, density 0 | 원본 그대로는 finger_pad가 ee_site보다 5.6 cm 뒤에 있어, 그리퍼가 버튼 속으로 약 5.5 cm 들어간 뒤에야 닿는다. 손목 캡슐 앞끝(ee_site보다 12 mm 앞)이 버튼을 누르게 했다 |
| 버튼 개수 | 1개 (`elevator_button_3`, 패널 가운데) | 6개 (`elevator_button_1`~`6`, 1~6층) | 층을 고르는 명령을 다루기 위해 |
| 버튼 위치 | 패널 기준 (0, 0.065, 0) | 패널 기준 (x, 0.065, z). P1 (0.07, −0.06), P2 (−0.07, −0.06), P3 (0.07, 0.04), P4 (−0.07, 0.04), P5 (0.07, 0.14), P6 (−0.07, 0.14). 기본 배치는 k층이 Pk(정면에서 아래부터 '1 2 / 3 4 / 5 6') | 패널 안에 2열 3행으로 놓기 위해 |
| 버튼 반지름 | 0.045 m | 0.035 m | 6개가 패널 안에 서로 떨어져 들어가도록 |
| 버튼 slide 관절 | `button_3_slide` (축 (0, −1, 0), 범위 0~0.015 m, stiffness 220, damping 3) | 층마다 같은 설정의 `button_{n}_slide` | 원본 버튼의 동역학을 그대로 유지 |
| 숫자 라벨 | 없음 | 버튼마다 얇은 상자 `label_{n}`: 반폭 0.58 × 반지름, 반두께 0.0004 m, 중심 pos (0, 0.0156, 0)이라 라벨 앞면이 버튼 앞면보다 1 mm 앞(이 앞면 중심이 인식·IK의 기준점 '라벨 중심'), 충돌 없음, 질량 0. 재질 `digit_{n}`(128×128 숫자 그림 텍스처) | 카메라로 층을 읽기 위해. 라벨이 버튼 테두리에 닿으면 파란 고리가 끊겨 분할이 실패하므로 반폭을 0.58 × 반지름으로 두었다 |
| 숫자 그림 | 없음 | 밝은 바탕 (245, 245, 240), 어두운 숫자 (15, 15, 15), Pillow 기본 글꼴 102 크기, 글자를 그림 가운데에 맞춤. 뒤집지 않아도 정면에서 바로 읽힌다(MuJoCo 4.0.1, macOS에서 확인) | 인식 템플릿도 같은 그림에서 만든다 |
| `button_target` site | 버튼 앞면보다 25 mm 앞의 노란 site | 삭제(버튼 body를 통째로 교체하면서 함께 없어짐) | 정답 좌표라 제어에 쓰지 않는다. 원본에서 ee_site를 여기로 보내면 버튼 변위가 0 mm임을 확인했다(`tests/test_control.py`) |
| 전체 뷰 카메라 | 없음 | `overview`: 위치 (1.35, 0.35, 1.55), (0.25, −0.50, 0.92)를 바라봄, fovy 55° | 녹화용. 인식에는 쓰지 않는다 |

바꾸지 않은 것: 휠체어, 팔 관절 범위·액추에이터(kp, kv), 패널 크기·위치, 조명 정의, head 카메라(`head_rgb`, fovy 72°), 탁자와 큐브, timestep 0.002 s.

## 2. 실행 설정 (모델 파일 밖)

| 항목 | 원본 기본 | 이 구현 | 코드 |
|---|---|---|---|
| 깊이 사용 | 사용 안 함 | head 카메라의 깊이 영상(광축 방향 거리, m)을 RGB와 함께 인식에 쓴다 | `camera.capture` |
| 인식 해상도 | 640×480 | 1280×960 (`mujoco.Renderer(model, height=960, width=1280)`) | `Scene.renderer` |
| 시작·대기 자세 | 모든 관절 0 | 관찰 자세 [0, 0, −1.6, 0, 0, 0], 그리퍼 ctrl 0. reset에서 qpos와 ctrl을 같이 넣고 0.5초 안정화한다. q = 0이면 높이 약 0.96 m 아래 버튼이 팔에 가려지기 때문이다 | `Scene.reset` |
| 녹화 화면 | - | 전체 뷰와 head 카메라를 각 640×480으로 따로 렌더링한다(판단에 쓰지 않음) | `src/assist/record.py` |

## 3. 평가용 무작위화 (실행 중에 모델 값을 바꿈)

`Scene.reset(dpos, yaw_deg, light)`가 시행마다 적용한다. 조건 값은 부록 E 규칙으로 시드에서 뽑아 `data/eval_protocol.json`에 적었다.

| 항목 | 방법 | 범위 (기본 / 변화) |
|---|---|---|
| 패널 이동 | `model.body_pos[패널]`에 이동을 더한다 | x·y·z 각 ±3 cm / x·z ±10 cm, y ±5 cm |
| 패널 회전 | 패널 body 원점을 지나는 월드 +z축 기준, 위에서 보아 반시계가 + (`model.body_quat[패널]`) | 0° / ±10° |
| 조명 배율 | `model.light_diffuse`, `model.vis.headlight.diffuse`, `model.vis.headlight.ambient`에 같은 배율을 곱한다. `light_diffuse`만 바꾸면 패널 밝기가 거의 변하지 않는다(패널 밝기의 약 90%가 기본 headlight에서 온다) | 1.0 / 0.6~1.2배 |
| 숫자 배치 섞기 | `rng.permutation(6)`의 결과로 (perm[i]+1)층을 P(i+1)에 둔다. 배치가 바뀌면 `build/scene.xml`을 다시 만든다 | 기본 배치 / 섞기 |
