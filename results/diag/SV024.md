# SV024 실패 원인 재확인 (확인만, 2026-11-24)

코드와 문서는 고치지 않았다. 확인 스크립트: `experiments/diag/sv024.py`(`.venv/bin/python`으로 실행). 수치 원본: `SV024.json`.
장면은 추가 시험과 같은 조건(`variation_trial("SV024", 4024)`)으로 만들고, 파이프라인과 같은 시점(reset 직후)에 head_rgb 1280×960 RGB·깊이를 찍었다.
라벨 중심과 가림 판정에는 채점용 정답(`Scene.truth()`)과 `mj_ray`를 썼다. 인식은 `perception.detect`를 그대로 불렀다.

| 패널 이동 / 회전 / 조명 | (+0.29, −1.57, −9.48) cm / +6.15° / 0.878배 |
| 숫자 배치 | 453621 |
| 다시 찍은 인식 결과 | 1, 2, 3, 6층 (추가 시험 기록의 `seen_floors` 1236과 같음). 4·5층 미검출 |

## 판정: **가림** (화면 경계 아님)

4·5층 버튼의 **아래쪽 일부가 팔 베이스(link1의 이름 없는 geom, 빨간 원통)에 가렸다.**
그래서 파란 고리가 닫히지 않았고, 라벨 픽셀을 떼어 내지 못해 인식에서 빠졌다. 두 버튼 모두 카메라 화면 안쪽 깊숙이 있다.

가림 판정: 그 픽셀의 깊이(광축 거리)가 라벨까지의 광축 거리보다 2 mm 넘게 짧으면 가림으로 봤다.
가린 geom은 카메라에서 각 표본점으로 쏜 `mj_ray`의 첫 충돌로 찾았다.

### 인식 단계별

| 단계 (부록 B) | 4층 | 5층 |
|---|---|---|
| 파란 영역 (화면 안 고리 표본 96점 중 파란 픽셀) | 61 | 50 |
| 팽창 후 성분 크기 ≥ 60 px | 1170 px, 통과 | 1179 px, 통과 |
| 구멍 채우기로 채운 픽셀 | **0** (고리가 닫히지 않음) | **0** |
| 가장 큰 라벨 덩어리 ≥ 25 px | **3 px, 미달** | **5 px, 미달** |
| 판독 점수 | 판독까지 가지 않음 | 판독까지 가지 않음 |
| **빠진 단계** | **라벨 픽셀** | **라벨 픽셀** |

라벨 픽셀은 '구멍을 채운 성분을 2회 침식한 영역 안의, 파랗지 않고 S < 0.30인 픽셀'이다.
고리 아래쪽이 팔 베이스에 덮여 끊기면 라벨 자리가 구멍이 아니라 바깥과 이어진 영역이 되어 채워지지 않는다.
그래서 라벨 픽셀이 거의 남지 않는다. 계획서 3절의 '라벨이 테두리에 닿으면 고리가 끊겨 분할이 실패' 현상과 같은 방식이다.

### 반사실 확인
메모리 안 모델에서 link1의 geom만 투명하게(rgba 알파 0) 하고 같은 시점에 다시 찍었다. 그러자 **1~6층 모두 검출**됐다(4층 점수 0.916·여유 0.241, 5층 0.901·0.059). 다른 조건은 그대로다.

## 영상에서 '화면 아래 경계에 잘린 것'으로 보인 이유

녹화 영상(`results/video/SV024_*.mp4`) 오른쪽 위의 확대 화면(zoom x2)은 head 원본 전체가 아니다.
**검출된 층 중심들의 평균을 가운데로 원본에서 300×240만 잘라낸 것이다**(`src/assist/record.py`의 `_head_overlay`).
SV024에서는 검출된 1·2·3·6층 평균을 가운데로 잘라서 확대 화면 범위가 v 486~726이다.

| | 4층 | 5층 |
|---|---|---|
| 확대 화면 안에 고리가 다 들어감 | 예 | **아니오, 아래 경계보다 2.3 px 아래까지** |

그래서 영상의 확대 화면에서는 5층 버튼 아래가 화면 경계에 잘린 것처럼 보인다. 실제 카메라 화면(v 0~959)에서는 버튼 아래로 230 px 넘게 여유가 있다.
4층이 '온전히 보이는' 것처럼 보인 것은, 가린 부분이 고리 아래쪽 일부(표본 30/96)와 라벨 아래 가장자리(12/81)뿐이라 확대 화면에서 눈에 잘 띄지 않았기 때문으로 보인다.
